## Outcome

cortex's specification is validated and generated by ESS 0.55.0, the newest release, locally and in
CI, and `task check` passes with the `ess` 0.55.0 binary.

## Why

The workspace rule is to use the newest ESS release everywhere and to move a repository's ESS pin
when a release ships. `spec/ess-inputs.yaml` requires `ess 0.52.0`, and every `--strict-requires`
step refuses a newer binary: with `ess` 0.55.0 on `PATH`, `task docs-check` exits 201 ("requires
ess 0.52.0 and this is ess 0.55.0, which is newer, and --strict-requires refuses a newer release",
measured 2026-10-07 in wave 20261006i).

## Work

1. `spec/ess-inputs.yaml`: `requires: ess 0.55.0`. The source format stays `ess/20` unless 0.55.0
   refuses it.
2. `task generate` with `ess` 0.55.0: `generated/`, `spec/suite.json` and the derived site files.
3. Make the crate build against the regenerated code. ESS 0.55.0 changes the context port: a
   `{generated: true}` payload value of type `Optional<T>` is read from a new
   `generate_optional_<t>` method (beyond10x/ess#467); a context that implements the port adds it.
4. `.github/workflows/check.yml`: `ESS_VERSION` 0.55.0 and its `ESS_SHA256`
   (`1d2c0f0ad6871eafa452d738d2bc978e748349683f77667371cefebc7f646a8c` for
   `ess-0.55.0-x86_64-unknown-linux-gnu.tar.gz`, from the release's `SHA256SUMS`).
5. `AGENTS.md`: the pin sentence and the upstream-facts row that cites ESS 0.52.0, checked against
   0.55.0's output.

## Acceptance

- `task check ESS=<ess 0.55.0>` exits 0, every step, including `drift` and `docs-check`.
- `ess specify validate --path spec --strict-requires` with 0.55.0 exits 0 and with 0.52.0 refuses
  the newer requirement.
- The `Check` workflow on the pull request installs 0.55.0 and passes.

## Not in this story

The two `UNMAPPED:` notes on `QualityMeasured` and `SchemaChangesProposed`
(`spec/domains/instance.yaml`, `rate` and `cost_usd` left off the events because ESS 0.52.0 filled an
`Optional` `{generated: true}` field with a constant `None`) may be settled by 0.55.0's context port;
moving those fields onto the events is a separate story.
